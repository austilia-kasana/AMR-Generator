# 1.3.4 修复：决议文本乱码

## 现象

一键三级决议的标题/描述在游戏里显示乱码或被截断。之前 1.3 的文案是正常的，这次改了描述之后出现。

## 根因

描述里新增了“不会增加发展度”，其中 **“会”** 的字库编码是：

```text
0x10 0x1A 0x4F
```

`0x1A` 是 SUB 控制字符。EU4 的 localisation 行解析会把 `0x1A` 当作控制/终止符，导致这一行从“会”处被截断或显示乱码。旧文案里没有这个字，所以之前正常。

## 修复

1. 文案改成“已三级的**不再**增加发展度”，避开 `0x1A`。
2. `_zh()` 编码后增加检查：只要编码里出现 `0x0A` / `0x0D` / `0x1A`，这条文案**退回英文**，并在生成日志里点名，绝不写入会断行的中文。
3. 生成日志会显示被退回的键，例如 `AMR_hidden_locked_tt`。

## 验证

- 新的决议描述解码正常：
  > 点一次，你名下所有未满三级的奇观升到三级。免费，每局只能用一次；已三级的不再增加发展度。没建、没拥有的不动。
- 决议描述行里不再有 `0x1A`
- 117 例测试全过

## 注意

需要重新生成构建并**完全重启游戏**；旧存档里已经显示乱码的决议文本不会自己修复。
